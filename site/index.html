lazyOS_

Debian for ARM Chromebooks. Keyboard first. Lazy by design.

Real Debian above the kernel, postmarketOS-grade hardware support below it, and a swayfx session where the thing to press is always on the screen. The system does the boring part.

LAZY, ON PURPOSE

Features that are one script each

No daemons waiting around. Each feature is a small script you can read, and anything that takes seconds says so.

AI agents, built in

Launch Claude Code, Codex, OpenCode, Gemini or Copilot from one menu, install them into ~/.local, and keep separate accounts per agent.

Dictation, offline

parecord → whisper-cli → wtype. The model is fetched and verified on first use. No daemon.

Slow actions say so twice

A scan or a connection opens a notification that becomes the result, plus a spinner on the bar with the task's name. Both vanish when it's done.

Learn, on the machine

A seven-page manual in the launcher, rendered with glow in the terminal: welcome, rofi, shortcuts, software, the system, troubleshooting, agents.

A terminal with taste

eza, bat, zoxide, fzf, ripgrep, starship, lazygit, btop, tmux, yt-dlp and friends, ready from the first login.

One command health check

check-system.sh prints OK/WARN/FAIL, one line per check, and verifies the machine still matches the repository it was built from.

FOUR STEPS

Install from a microSD card

The release image boots from external storage on the stock ChromeOS firmware. Install to internal storage later, from the running card.

Download the release

Get google-asurada.img.xz and SHA256SUMS from the v0.3.0 release.

Verify and write the card

$ sha256sum -c SHA256SUMS
$ xz -dc google-asurada.img.xz | sudo dd of=/dev/mmcblk1 bs=4M conv=fsync

Replace /dev/mmcblk1 with your card's device. dd overwrites it.

Allow external boot on the Chromebook

Enter developer mode, then from a shell:

$ crossystem dev_boot_usb=1 dev_boot_signed_only=0

Insert the card and pick external disk in the firmware menu.

Log in, then change the password

It comes up to a greetd prompt: user brunux, password debian, passwordless sudo. Run passwd before using it for anything real.

Read before you flash. The firmware is never touched: the boot chain is the stock signed kernel partition. But developer mode wipes ChromeOS, and installing to internal storage (CONFIRM=yes sudo scripts/install-emmc.sh) erases it. Keep a second computer and recovery media at hand.

UNDER THE HOOD

Not a remix. A port.

LazyOS reuses the hardware support of Nura, the postmarketOS-based system it started from: the kernel, device tree, patches, modules and boot flow. Debian supplies everything above the kernel.

The port framework is device-agnostic: a new Chromebook is a new devices/<codename>/ directory, and a new kernel only when the kernel differs. Every release is checked on real hardware, and the reports live in the repository.
